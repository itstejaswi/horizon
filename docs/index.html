A local-first personal AI tool using Ollama for local inference — chat, documents, prompts, memory, reusable agents and scheduled workflows. Local inference stays on your hardware; enabled external tools may use the network.

Verify it, don't trust it.

Strong claims, so each one is checkable.

Nothing is collected

No telemetry, analytics or Horizon account. Local inference needs no API key. External integrations may require their own sign-in.

You can watch it

The configurable Traffic log shows chat exchanges with 127.0.0.1. Agents records bounded tool-call history on disk. Neither is a system-wide network audit.

Local inference

Ollama serves the selected model on loopback. Horizon owns the agent harness and tool permissions; the Human remains in control through the web UI. Replies can be read aloud with verified-local browser voices, without microphone recording or a cloud voice fallback.

External capabilities are your choice

Link reading, browser automation, configured commands and MCP servers can use the network when enabled. Keep them off for local-only work. File workflows can run without a model or network.

Is this the right tool for you?

Worth being honest early.

Use Open WebUI or AnythingLLM if…

…you want one interface across many providers — OpenAI, Anthropic, Ollama and others. Both are mature and have far more features than this.

Use Horizon if…

…you want one local inference runtime and a Horizon-owned agent harness. Ollama supplies inference; Horizon controls tool grants, approvals and run state. No Docker, no Electron.

How it works

Local inference. Your browser talks only to Horizon's Node.js server, which sends requests to Ollama on loopback.

browser
  ↳ 127.0.0.1:3000   Horizon's Node.js server
      ↳ 127.0.0.1:11434   Ollama native API  →  the selected model   CPU or GPU

Horizon defaults to the Ollama loopback service and the qwen3:1.7b model. Horizon's Node.js runtime owns orchestration and the Human at the web UI remains the authority.

Ordinary prompts can use permitted tools directly, with inline activity and per-call approval for anything beyond read-only file access. Configure access once in Agents settings; no saved agent is needed for conversation tools.

Optional agents add a bounded tool-execution loop, fixed workflows, approvals and persistent interval schedules. The local server must remain running and the computer awake. Missed runs are skipped, not replayed. Agent settings and run history are stored on disk, separately from browser chat data.

Experimental native planning is opt-in and model-dependent: it persists concrete steps and supports independent file readback and predicate checks on fresh read results. Only explicitly transient read-only failures may retry once, within the run's call budget. Existing permissions and approvals are unchanged. This is not adaptive replanning or general semantic proof that a request was fulfilled.

OpenClaw is not installed or executed as a runtime. Only selected source patterns inform the Horizon-owned harness. Read aloud is independent local browser/Windows speech synthesis; microphone recording and dictation are not provided.

Install

Two one-time installs, then a double-click. Pick whichever column sounds like you.

The simple way

no terminal

If you have never used a command line, follow this.

1

Install the two pieces

Download and run each installer. Both links go to the official source:

Ollama ollama.com
Node.js — choose the LTS version nodejs.org

Install Ollama and Node.js 20 or later. Accept the installer defaults and restart if either asks.

2

Download Horizon

On the project page, click the green Code button, then Download ZIP.

3

Unblock it, then extract

Windows marks files that come from the internet. Clearing it on the ZIP saves clearing it on every file inside.

Right-click the ZIP → Properties → tick Unblock → OK. Then right-click → Extract All… into a folder that belongs to you, such as Documents\horizon.

No Unblock box? Nothing to clear — carry on.

4

Double-click Start Horizon.bat

A small black window opens — that is the server, and it stays open while Horizon runs. Your browser opens at http://127.0.0.1:3000.

Before the first chat, run Setup-Horizon.ps1 once from PowerShell to check prerequisites and prepare the configured qwen3:1.7b model. If Windows says “Windows protected your PC”, click More info → Run anyway.

Do not close that black window to quit. It is the server: closing it kills Horizon mid-request and leaves the model orphaned in memory. Use the power button in Horizon for a safe exit.

For developers

git

Cloning skips the unblock step — Git-created files are not tagged.

1

Dependencies

winget install OpenJS.NodeJS.LTS

Install Ollama separately from ollama.com/download. No winget? It ships with Windows 11 and recent Windows 10, but not every machine has it. Use the installers in the column on the left instead — same software, same sources.

2

Clone and run

git clone https://github.com/itstejaswi/horizon
cd horizon
.\"Start Horizon.bat"

Initial setup installs Horizon's declared dependencies and its isolated Chromium browser. The custom MCP client ships as source with Horizon; it is not installed separately. Features remain off until enabled. Configured third-party MCP servers are separate programs with their own installation requirements.

3

Or use the PowerShell launcher

.\scripts\Start-Horizon.ps1

Use Setup-Horizon.ps1 to check prerequisites and prepare the configured model. The launcher can start Ollama when configured; Stop unloads Horizon's model but leaves Ollama running. -WebPort, -ModelAlias and -NoBrowser are accepted.

4

Tests and tooling

npm test     # regression tests, no model needed
npm run check
npm run build

These are acceptance commands for an isolated environment; none were run for this source-only update.
