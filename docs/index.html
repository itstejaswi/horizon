No account. No internet. No data leaving this computer.

Those are strong claims, so Horizon is built so you can check them rather than trust them.

Nothing is collected

No telemetry, no analytics, no account, no API key. Horizon talks to exactly one address: the Foundry service on your own machine.

You can watch it

The Traffic panel records every request and response. Read the whole exchange and see that it only ever goes to 127.0.0.1.

It works offline

Once your models are cached, pull the network cable. The air-gap indicator notices passively — Horizon never makes a request to test for internet.

Is this the right tool for you?

Probably worth being honest about this early.

Use Open WebUI or AnythingLLM if…

…you want one interface across many providers — OpenAI, Anthropic, Ollama, Foundry Local and more. Both are mature, well supported, and have far more features than this does. Point them at Foundry Local's endpoint and they work.

Use Horizon if…

…you want the opposite trade: one runtime, understood properly. Horizon starts and stops the service, loads and unloads models, re-discovers the port when Foundry restarts, and gives the memory back when you are done. No Docker, no Electron, no account.

How it works

Four hops, all of them local. Your browser never talks to Foundry directly — it only talks to the small Node.js server in the project folder.

browser
  ↳ 127.0.0.1:3000   Horizon's Node.js server
      ↳ 127.0.0.1:<auto>   Foundry Local REST API
         ↳ the model   on your CPU, GPU or NPU

Foundry picks a new port on every restart. Horizon re-discovers it and reconnects on its own, mid-session, without losing your conversation.

Install

Two one-time installs, then a double-click. Internet is needed for setup only.

1

Install Foundry Local

winget install Microsoft.FoundryLocal
2

Install Node.js 18 or later

winget install OpenJS.NodeJS.LTS
3

Clone and run

git clone https://github.com/itstejaswi/horizon
cd horizon
.\"Start Horizon.bat"

No npm install. Horizon has no runtime dependencies.
